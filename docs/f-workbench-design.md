## 一、为什么要做这一轮

三份原型的血统关系决定了现状：

```
数模演易原型v2 (1.93M, 408 函数)        ← 同源通用版
      ↓ 裁掉数模内容
市调板块原型v1 (412K, 225 函数, 5 视图)  ← D:\腾龙\2026-10-13-10-00-20\
      ↓
市调板块原型v2 (1.82M, 原文件已丢)
      ↓ 机械搬运（build-port.mjs）
项目 PrototypeShell.vue + legacy/prototype/core.ts (237 函数)  ← 现在跑的
```

两者**本来就共用同一套青绿令牌**（v2 的 `--teal-500:#12A594` = 项目 `tokens.scss` 的 `--c-primary:#12a594`）。
所以「风格看齐」不是换配色，而是**布局范式与信息密度**看齐。差异集中在两处：

### 首页

| 区块 | 数模演易 v2 | 市调现版 |
|---|---|---|
| Hero / 真题轮播 / 输入区 | 有 | 有（文案已本地化） |
| 「全部真题」筛选 + 网格 | **三行 chips + 四列网格** | **完全没有** |
| 页面高度 | ~1800px | ~1080px |

### 工作台（重点）

| 元素 | 数模演易 v2 | 市调现版 |
|---|---|---|
| 顶栏步骤条 | ①全局分析→⑥论文 | 无 |
| 左栏 | 无（对话占满） | 任务列表常驻 |
| 右栏 | 产物抽屉（可收起） | 闸门/产物/演示 三 tab **常驻竖栏** |
| **人工决策** | **对话流里的卡片，读完就点** | **右栏独立面板，与对话分离** |

最后一行是这一轮的核心判断：数模把「确认」做成对话流中的一张卡，用户读完分析紧接着就能点；
市调现版把它挪到右栏，视线要在两块区域之间来回跳，「商量」的语感就没了。
本轮的决策卡按前者做。

## 三、契约要点

### 组件是纯受控的

不 fetch、不读写 localStorage、不碰 Pinia。所有状态由 props 进，所有动作 emit 出。
这样正式接入时换数据源不需要改组件。

### 状态全部推导，不落盘布尔

```ts
resolveSteps(activeKey, confirmedKeys)  // 步骤条的 done/active/todo 由「已确认集合」推
```

`confirmedKeys` 里没有的一律算 todo —— 当前阶段之前但没确认过的，**不假装做过**。
好处是「回到上一步」重选后状态自动回退，不需要写清空逻辑。

### 决策卡的三条纪律

1. **已确认的卡不折叠、不消失**，保留标题与正文，只在下方追加结论。
   复核者回头看对话时必须能读懂「当时在确认什么」。
2. 已确认仍给「改一下」，且是**顺着原来那张卡**回到未答，不新开一张。
3. 只读态按钮 disabled，但结论照常显示 —— **只读不该抹掉状态信息**（阶段 6 踩过的坑，这里提前执行）。

### 决策选项的两种形态

- 普通选项：点完直接 emit
- `key` 以 `note:` 开头：先展开文本框，填完再 emit（用于「补充约束」「换一种方法」这类需要说清依据的）

### 与数模原型的有意偏差

**年份筛选行不渲染。** 数模 v2 显示了「年份：全部 / 2026」这一行，但只有一个真实取值，等于废行。
本轮改为「取值不足两个的维度自动跳过」。现行实现见 `src/components/home/HomeCaseGrid.vue`
（三行筛选：组别 / 领域 / 届次），要改跳过规则就在它的 `facets` 计算里改，一行的事。

## 五、还没做的

1. **没有业务宿主**。工作台还没接进 `ResearchWorkspaceView`，目前只能从 `/dev/research/workbench` 看。
   接进去要决定：六阶段编辑器（阶段 1–6 组件）是嵌在对话流里，还是仍然放独立区域？
2. ~~**首页没有真的接进首页**~~ —— 已解决。首页改为 `ResearchHomeView.vue` 直接对齐原型，
   `HomeCaseGrid` 就地嵌在其中，不再依赖 `PrototypeShell.vue`（那个文件是原型机械生成的，
   注释明写「改 id/class 会静默打断 162 个原型函数」，本轮没有动它）。
   详见 `docs/f-home-prototype-alignment.md`。
3. **六阶段编辑器本身的风格没动**。它们与工作台共用同一套令牌，但信息密度更接近「表单」而非「对话」。
   要不要把它们也改轻（更少边框、更大留白），等看完工作台效果再定。
4. **决策卡的「下游失效」标记没做**。现在「改一下」只回退阶段，下游已生成的消息保留原样。
   正式接入时应给它们打「基于旧决策，需重跑」的标记 —— 契约里预留了位置，但没有实现。
5. **没有流式输出**。消息是整条渲染的，不是逐字吐。这属于后端推送形态，接入时再定。
