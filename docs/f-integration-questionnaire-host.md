## 2. 落盘兼容（重要）

`questionnaire` 是第 4 阶段才加的字段，旧记录里没有。`loadTopicPlanRecord` 必须按「缺失 → 补默认值」处理：

```ts
const questionnaire = value?.questionnaire === undefined
  ? emptyQuestionnaireDraft()
  : normalizeQuestionnaireDraft(value.questionnaire)
if (!topic || !plan || !questionnaire) return emptyTopicPlanRecord()
```

写成「拒绝」会让 10-26 之前存过第 2、3 阶段草稿的用户整份记录作废。这与交接文档里给 P 的 `cleanTask` 建议是同一条纪律。

## 3. 上游只给了「研究方案」，没给赛事与方向

第 4 阶段的 `upstream` 按已确认提案收成一层 `{ plan }`。宿主因此只传 `localTaskId`，不再传 `competition`。上游条显示：

- 变量 N 个 / 分析计划 M 条
- 方案固定：已固定 / 尚未固定
- 本卷题目 N 题
- 已挂变量 N / M（有未挂变量的题会标黄）

第三个提示只在「方案固定后又被改动」时出现（`adoptionState(plan) === 'drifted'`），提醒用户回来核对映射下拉里的选项。

## 5. 未验

- **只读态**：工作台不传 `readOnly`，宿主这一层没有入口可验。
- **陈旧事件拒绝**：UI 上构造不出「旧 revision 的 emit」，与阶段 2、3 同一缺口。
- **「本机保存 → 切任务 → 刷新恢复」全链路**：草稿仍存在 F 侧的 `scdc-f-topic-plan-v1:<id>`，不在 P 的 `LocalResearchTask` 里，跨设备不成立。
- **正式保存**：接口未接入。
