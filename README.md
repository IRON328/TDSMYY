# 拒绝脑补：前端备份与双版本管理

日常前端开发在 **D:/scdc-develop**；本仓库负责备份、版本标注和恢复，不另维护一套产品。后端 **D:/mgy** 暂不由本次工作负责。

| 保留位置 | 用途 | 代码分支 | 实际状态 |
| --- | --- | --- | --- |
| **当前稳定版** | 最近一次完成约定验收的版本 | `stable/current` | **待建立**：尚未上传并验收前端代码 |
| **上一稳定版** | 当前版之前的稳定恢复点 | `stable/previous` | **待建立**：尚无第二个已验证版本 |

每版记录编号、时间、完整提交SHA、功能、变化、验证证据、已知问题、运行方式、后端依赖、数据兼容与恢复步骤。详见[双版本说明](VERSIONS.md)及[状态登记](versions/registry.json)。目前不创建空代码分支或复制同一提交充数。

`main` 当前展示管理说明，不是可恢复的前端代码版本；未验收中间备份使用 `backup/frontend`。两个稳定位置轮换，Git提交历史继续保留，不通过重写历史只剩两次提交。原型归档不占这两个位置。

新版本通过约定检查后，先保留原当前版为上一版，再更新当前版并核对远端SHA。上传成功只证明备份完成，不能证明版本稳定。GitHub主分支保护尚未启用，书面约定不等于服务端强制保护。


原型基线保存在独立的私有[原型归档仓库](https://github.com/Mgy-d/jujue-naobu-prototype-archive)。A/B方案文档保留在[草稿PR #1](https://github.com/Mgy-d/jujue-naobu-workbench/pull/1)，不因备份规则而自动开始产品开发。

备份只纳入源码、锁文件、必要配置模板、可发布资源和测试；密钥、账号、真实答卷、运行数据、node_modules、dist和本机配置不上传。

管理文件检查：运行 python scripts/check_repository.py，并人工检查差异。
